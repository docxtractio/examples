# Security

Report suspected vulnerabilities privately to **support@docxtract.io** with the subject
**Security report: DocXtract examples**. Do not report vulnerabilities in a public issue.

Include the affected app and version/commit, reproduction steps using synthetic data, and
the potential impact. Do not send API keys, personal documents or customer extraction data.
Coordinate public disclosure with the maintainers after a fix is available.

These apps are local examples bound to loopback. A hosted adaptation needs authentication,
server-managed secrets and deployment-specific security controls. Use the latest maintained
SDK release when assessing a report.
